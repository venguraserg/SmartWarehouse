# SmartWarehouse

Складской учёт запасных частей и расходных материалов отдела эксплуатации технологического оборудования.

**Стек:** ASP.NET Core Web API (.NET 10), EF Core + PostgreSQL, веб-интерфейс на Blazor. Позже: мобильный клиент.

## Структура

| Проект | Назначение |
|---|---|
| `SmartWarehouse.Domain` | Сущности и правила предметной области. Ни от чего не зависит |
| `SmartWarehouse.Application` | Сервисы (документы и остатки, справочники, места хранения), DTO, интерфейсы репозиториев |
| `SmartWarehouse.Infrastructure` | EF Core, `WarehouseDbContext`, конфигурации таблиц, репозитории, начальное заполнение |
| `SmartWarehouse.API` | REST API, обработка ошибок |
| `SmartWarehouse.Web` | Веб-интерфейс (Blazor, интерактивный серверный режим). Работает только через API |
| `SmartWarehouse.Tests` | Модульные тесты бизнес-правил (xUnit) |

## Вход и роли

При первом запуске API создаёт администратора: логин **`admin`**, пароль **`admin123`**
(или значение `Auth:InitialAdminPassword`). При первом входе программа попросит сменить пароль.
Затем в разделе **Администрирование → Пользователи** заведите учётные записи сотрудникам.

| Роль | Что может |
|---|---|
| Сотрудник | свой подотчёт, просмотр остатков (акты на списание — в следующей версии) |
| Руководитель | + подотчёт подчинённых (по полю «Руководитель» у сотрудника, по всей цепочке) |
| Старший смены | в смены без кладовщика: выдача со склада (в том числе себе) и приём возврата; видит весь подотчёт. Приход, перемещение, корректировка, справочники — нет. Назначает администратор галочкой в «Пользователях» |
| Кладовщик | приход, выдача, возврат, списание, перемещение, корректировка; номенклатура, склады, справочники |
| Администратор | всё, а также пользователи и справочник сотрудников, исправление цены партии |

Цены и стоимость видят руководитель, кладовщик и администратор; рядовому сотруднику API их не отдаёт.

- Пароли хранятся только в виде хеша (PBKDF2 с солью). Администратор может задать временный пароль.
- API принимает запросы только с токеном (`Authorization: Bearer …`), который выдаёт `POST /api/auth/login`.
- Ключ подписи токенов — настройка `Auth:JwtKey` (не короче 32 символов). В разработке (запуск из Visual Studio)
  без настройки используется постоянный ключ разработки — вход не сбрасывается при перезапуске API.
  На сервере ключ обязателен: в Docker задаётся в `.env` (`JWT_KEY`).

## Модель данных

| Сущность | Таблица | Назначение |
|---|---|---|
| `Category` | `categories` | Категории номенклатуры |
| `UnitOfMeasure` | `units` | Единицы измерения; признак `IsFractional` разрешает дробное количество |
| `Item` | `items` | Номенклатура: артикул, наименование, категория, единица, мин./макс. остаток |
| `ItemImage` | `item_images` | Фото позиции (одно, JPEG/PNG/WebP до 5 МБ), хранится в БД |
| `Warehouse` | `warehouses` | Склад с коротким кодом (`WH1`) |
| `StorageLocation` | `storage_locations` | Дерево мест: зона → стеллаж → полка → ячейка. `FullCode` (`WH1-A-01-03`) — содержимое QR-метки. `Name` — описание («Подшипники 62xx»): обязательно для новых и изменяемых мест; в складских операциях место выбирают по нему (описание · код) |
| `StockDocument` | `stock_documents` | Документ: приход, выдача, перемещение, списание, корректировка. Номер `ПР-000015`, `ВЫД-000102`... |
| `Batch` | `batches` | Партия: позиция, цена за единицу, дата и документ прихода. Каждая строка прихода — своя партия; партия идёт за товаром: ячейка → сотрудник → акт. По умолчанию берётся самая старая (FIFO), её можно сменить. Остатки до введения цен — партия «без цены», цену указывает администратор в карточке позиции |
| `StockMovement` | `stock_movements` | Строка документа и запись журнала движений (с партией) |
| `StockBalance` | `stock_balances` | Текущий остаток позиции в месте хранения по партиям |
| `AppSetting` | `app_settings` | Настройки, которые меняет администратор: наклейки, шаблон акта (JSON по разделам) |
| `Employee` | `employees` | Сотрудники: табельный номер, ФИО, должность, подразделение, телефон, признак «работает». В документах — кто провёл и кому выдано |
| `EmployeeBalance` | `employee_balances` | Подотчёт: сколько позиции числится за сотрудником по партиям (выдано, но не списано и не возвращено) |
| `Equipment` | `equipment` | Дерево оборудования: участок → установка → узел |

Единицы `шт`, `компл`, `упак`, `м`, `кг`, `л` создаются автоматически при первом запуске.

## Приход и справочники: новое на ходу

Если позиции нет в номенклатуре, её заводят прямо из прихода — документ остаётся заполненным:
- в строке, где позиция не нашлась, кнопка **«+ создать новую»** (введённый текст подставится в наименование или артикул);
- незнакомый штрих-код, отсканированный в приходе, сразу открывает ту же форму со штрих-кодом.

Нужны наименование, артикул (подставляется следующий свободный по категории) и единица; после создания позиция встаёт в строку.

Так же на ходу (кнопка **«+»** рядом со списком; кладовщик и администратор) создаются и другие элементы справочников:
- **категория** и **единица измерения** — в форме новой позиции (из прихода и в карточке позиции);
- **место хранения** — в колонке «Куда» (приход, возврат, перемещение, корректировка): где, тип, код, описание; новое место сразу выбирается в строке;
- **оборудование** — в выдаче и в акте на списание.
Введённые данные документа при этом сохраняются. Enter в таком блоке нажимает его «Создать», а не проводит документ.

## Правила учёта

- Остаток (`StockBalance`) **нельзя изменить напрямую** — только проведением документа.
- Документ проводится **целиком или не проводится вовсе**: если хоть одна строка ошибочна, не меняется ничего.
- Уйти в минус нельзя: это проверяет сервис, дополнительно стоит ограничение в БД.
  От одновременного расхода одного остатка двумя пользователями защищает версия строки
  (`xmin` PostgreSQL); в таком случае API отвечает `409`.
- Товар хранится только в **конечных** местах (без вложенных). В место, где лежит товар, нельзя добавить вложенное.
- Вложенность мест только «вниз»: зона → стеллаж → полка → ячейка (уровни можно пропускать).
- Для штучных единиц количество должно быть целым.

| Тип документа | `fromLocationId` в строке | `toLocationId` в строке |
|---|---|---|
| `Receipt` — приход | — | обязательно |
| `Issue` — выдача сотруднику (`receivedById` обязателен, можно `equipmentId`): товар уходит из ячейки и числится за сотрудником | обязательно | — |
| `Transfer` — перемещение | обязательно | обязательно, другое место |
| `WriteOff` — списание с сотрудника; **напрямую не проводится**, только утверждением акта на списание | — | — |
| `Return` — возврат от сотрудника на склад (`receivedById` обязателен) | — | обязательно |
| `Adjustment` — корректировка по инвентаризации | одно из двух: `to` увеличивает, `from` уменьшает | |

### Акты на списание

Сотрудник отчитывается, куда израсходовал полученное, — составляет **акт на списание** (на одну работу
или сводный за период; в каждой строке — оборудование и/или описание «куда использовано», можно дату).

| Состояние | Что происходит |
|---|---|
| Черновик | Сотрудник (или кладовщик за него) заполняет и правит; остатки не меняются |
| На утверждении | Позиции **зарезервированы**: их нельзя вернуть на склад или включить в другой акт. Можно отозвать |
| Утверждён | Руководитель утвердил — проведён документ списания (`СП-…`), позиции выбыли из учёта |
| Возвращён | Руководитель вернул с замечанием; резерв снят, сотрудник исправляет и отправляет снова |

- Утверждает **непосредственный руководитель** сотрудника (поле «Руководитель» в карточке). У кого руководителя нет —
  утверждает сам: при отправке акт сразу утверждается.
- PDF акта: неутверждённый — с надписью «ЧЕРНОВИК» / «НА УТВЕРЖДЕНИИ», утверждённый — с отметкой, кто и когда утвердил.
  Подписи комиссии — пустыми строками.
- В подотчёте видно, **сколько дней** числится позиция (по самой ранней невозвращённой выдаче); давнее подсвечивается.
  Порог — `Custody:AgeWarningDays` в `SmartWarehouse.Web/appsettings.json` (по умолчанию 30).

## Запуск

### 1. Миграция БД

Если папки `SmartWarehouse.Infrastructure/Data/Migrations` ещё нет — создайте её и закоммитьте:

```bash
dotnet tool install --global dotnet-ef
dotnet ef migrations add InitialCreate -p SmartWarehouse.Infrastructure -s SmartWarehouse.API -o Data/Migrations
```

После изменения модели добавляйте новую миграцию с понятным именем, например `dotnet ef migrations add AddSuppliers ...`.

### 2. Локально (Visual Studio)

Строка подключения в репозитории не хранится. Правой кнопкой по `SmartWarehouse.API` →
**Manage User Secrets**, и впишите:

```json
{
  "ConnectionStrings": {
    "Default": "Host=localhost;Port=5432;Database=smartwarehouse;Username=postgres;Password=<пароль>"
  },
  "Database": { "MigrateOnStartup": true }
}
```

Запуск API и веб-интерфейса вместе: правой кнопкой по решению → **Configure Startup Projects** →
**Multiple startup projects** → для `SmartWarehouse.API` и `SmartWarehouse.Web` выберите **Start** → F5.

- API: http://localhost:5113
- Веб-интерфейс: http://localhost:5200 (адрес API задан в `SmartWarehouse.Web/appsettings.json`, `Api:BaseUrl`)

При первом запуске база и таблицы создадутся автоматически, справочник единиц заполнится.

### 3. Сервер на Windows (без Docker)

Отдельный ПК с Windows в сети предприятия: программа работает как службы Windows, PostgreSQL, ежедневные резервные копии.
Пошаговая инструкция — [deploy/windows/README.md](deploy/windows/README.md).

### 4. Docker (сервер на Linux)

```bash
cp .env.example .env      # задайте POSTGRES_PASSWORD и JWT_KEY
docker compose up -d --build
```

Веб-интерфейс — на порту `WEB_PORT` (по умолчанию 8081), API — на `API_PORT` (8080). Миграции применяются при старте.

## Телефон: сканирование и наклейки

- **Наклейки QR** (меню «Данные → Наклейки QR», кнопки «Наклейка QR» в карточке позиции и у места хранения):
  PDF на листы A4 с самоклеящимися наклейками — 3×7, 3×8, 4×10, 2×5; можно пропустить уже использованные наклейки листа
  и печатать несколько копий. Печатайте в масштабе **100 %** («Фактический размер»), без «Подогнать по странице».
- Что в QR-коде, выбирает администратор в **«Администрирование → Настройки»**:
  - **только код** (по умолчанию) — как напечатан на наклейке: код места `WH1-A-01` или артикул `SP-000012`.
    Распознают ручной сканер и сканер в приложении (в том числе на телефоне); обычная камера телефона покажет просто код;
  - **ссылка** на страницу ячейки (`/l/WH1-A-01`) или позиции (`/i/SP-000001`) — её открывает обычная камера телефона.
    Адрес в ссылке — из настроек, а если не указан — `App:PublicUrl` веб-приложения или адрес, по которому открыт сайт при печати.
  - Распознаются наклейки обоих видов — при смене настройки старые перепечатывать не нужно
    (а также первые наклейки с кодами `SWL-15` / `SWI-7`).
- **Коды — только латиницей**: склад и место хранения (`WH1-A-01`), артикул (`SP-000012`, буквы, цифры и `- . _ /`),
  штрих-код. Тогда ручной сканер вводит их при любой раскладке (набранное в русской раскладке приложение переводит обратно).
  В полях этих кодов русские буквы сразу заменяются латинскими с той же клавиши — как будто включена английская раскладка
  (переключать раскладку системы сайт не может).
  - Автоартикул: префикс категории — английское сокращение (`BRG-000001` — подшипники, задаётся в «Справочниках»),
    без категории или префикса — `SP-` (spare part).
  - Коды, введённые раньше кириллицей, миграция `LatinCodes` перевела в латиницу: `СК1` → `WH1`, `ЗЧ-` → `SP-`,
    остальные буквы — по звучанию (`Ж` → `ZH`). Наклейки с такими кодами нужно перепечатать, но сканер находит позицию
    и по старой наклейке. Если после перевода два кода совпали бы, коды этой таблицы не меняются — их правит администратор.
- **«📷 Сканировать»** — сканер внутри приложения (QR наших наклеек и заводские штрих-коды EAN/Code 128 на упаковке)
  и поле ввода для USB/Bluetooth-сканера. Заводской штрих-код указывается в карточке позиции.
  USB-сканер «печатает» как клавиатура; при русской раскладке приложение переводит набранное обратно.
- **Ручной сканер (USB / Bluetooth)** работает на любой странице без настройки: приложение узнаёт его по скорости ввода
  (символы идут через 5–30 мс и заканчиваются Enter или Tab) и убирает «напечатанное» из поля, если курсор стоял в нём.
  - на любой странице — открывается отсканированная ячейка или позиция;
  - в приходе, выдаче, возврате, перемещении, корректировке — позиция добавляется строкой (повторный скан — +1),
    QR ячейки подставляет «куда» / «откуда» (для перемещения — сначала откуда, затем куда);
  - в акте на списание — позиция из подотчёта добавляется строкой;
  - в карточке позиции (изменение) — код упаковки встаёт в поле «Штрих-код».
  - Поля поиска сканер заполняет как обычно. Если на компьютере включена русская раскладка, код всё равно распознаётся.
  - Сканер должен отправлять в конце **Enter** (так настроено у большинства по умолчанию) или Tab.
- **Установка на телефон**: в Chrome — меню ⋮ → «Добавить на главный экран» (значок «Склад», открывается сразу «Сканировать»).

### HTTPS для телефонов

Браузеры дают странице доступ к камере **только по https**. Без https работает сканирование наклеек камерой телефона
и ввод кода вручную; для сканера внутри приложения и заводских штрих-кодов нужен https.

**Вариант 1 — свой сертификат Caddy (без домена, в локальной сети):**

1. В `.env` укажите адрес сервера: `SITE_ADDRESS=192.168.1.10` (или имя, например `sklad.local`, если его знает DNS).
2. Запустите вместе с прокси:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
   ```
3. Возьмите корневой сертификат Caddy и установите его на каждый телефон (один раз):
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.https.yml cp caddy:/data/caddy/pki/authorities/local/root.crt ./sklad-root.crt
   ```
   Android: «Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС».
   iPhone: открыть файл, установить профиль, затем «Основные → Об этом устройстве → Доверие сертификатам» — включить.
4. Сайт открывается по `https://192.168.1.10` (порт 443).

**Вариант 2 — сертификат предприятия.** Если IT выдаёт сертификат на имя сервера (корпоративный центр сертификации уже
доверенный на телефонах), положите `server.crt` и `server.key` в папку `deploy/certs`, подключите её к контейнеру caddy
(`- ./deploy/certs:/certs:ro`) и в `deploy/Caddyfile` замените `tls internal` на `tls /certs/server.crt /certs/server.key`.

**Проверка с телефона при разработке.** В Visual Studio выберите для `SmartWarehouse.Web` профиль запуска **lan**:
сайт будет доступен с телефона по `http://<IP компьютера>:5200` (Windows спросит разрешение в брандмауэре).
Наклейки и ввод кода работают; камера в приложении — только на самом компьютере (`localhost` браузеры считают безопасным).
