# Сборка файла «Начальные остатки»

Скрипты собирают файл для импорта «Администрирование → Импорт начальных остатков» из двух источников:

- **сальдовые ведомости ТМЦ из 1С** (по всем МОЛ) — количество, цены, партии, коды, МОЛ;
- **ведомость склада** (ручная, Excel) — адреса хранения, уточнённые наименования, примечания, неучтённое и б/у.

```
pip install openpyxl
python3 -I parse1c.py data.json сальдовая_*.xlsx
python3 -I build.py data.json "ведомость склада.xlsx" out 16.11.2026 16.11.2026
#                    ^1С      ^ведомость             ^папка ^дата 1С  ^дата ведомости
```

В папке `out` будут два файла:

- **«Начальные остатки — готово»**. Лист «Импорт» загружается в приложение. Лист «В Сортировку» показывает партии без однозначного места.
- **«Начальные остатки — уточнить у персонала»**. Это партии, которые нельзя перенести без решения, и сверка количества.

## Правила

- **Адреса стеллажей** приводятся к виду Зона.Стеллаж.Полка.Ящик, где зона — этаж (`norm.py`):
  - `A5.1.3` → `1.A5.1.3`, `2A.5.1.3` → `2.A5.1.3`;
  - окончание «к» (коробка) убирается;
  - кириллица в адресе заменяется латиницей.
- **Сортировка.** Партия всё равно попадает в импорт, если:
  - адрес не по схеме;
  - в ведомости указано несколько мест;
  - кода нет в ведомости.

  Приложение кладёт её в место `SORT` «Сортировка», а прежнее место записывает в примечание партии.
- **Количество** берётся из 1С. Если 1С и ведомость расходятся, позиция попадает в лист «Сверка количества». Импорт это не блокирует.
- **Неучтённое и б/у** получают `Где = «Вне учёта»` и идут без цены. Артикул:
  - `БУ0006` → `BU0006`;
  - остальное — `NU-00001` (неучтённое) или `BU-00001` (б/у) по наименованию.
